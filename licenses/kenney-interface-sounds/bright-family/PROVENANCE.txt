Fruit game: brighter, lighter round sound family, v3
Prepared 2026-10-05 in a separate asset-only folder.
No Site checkout, application source, hosting, or deployed files were changed.
Application master gain remains 0.18; the exported audition uses native asset

READY ASSETS
button-soft-pon-v3.wav: 0.080 seconds; one higher rounded note.
fruit-soft-koron-v3.wav: 0.160 seconds; a soft two-note upward major third.
success-soft-v3.wav: 0.250 seconds; a short rising major triad.
retry-soft-v3.wav: 0.090 seconds; one brief higher neutral note.

These replace the v2 family in response to the user's actual listening feedback
that the previous sounds were dark. They are technically higher-pitched and
shorter. Every filename changes to v3 to avoid reuse of cached v2 resources.
The intended soft, non-metallic, child-friendly impression has not been verified
by listening. No actual audio-listening tool was used; technical signal tests
are not a claim of subjective audition.

WHAT CHANGED
Button: source pitch +2 semitones -> +14 semitones, one octave higher.
Landing: source pitches +2/-1 -> +14/+18 semitones; the lower second note is
replaced by a rising major third, second note at 82% relative gain.
Success: source pitches +2/+6/+9 -> +14/+18/+21 semitones, one octave higher.
Its note gains remain 0.84/0.91/1.00, with shorter 0/95/195 ms onset timing.
Retry: source pitch -3 -> +16 semitones, replacing the low error-like reply.

Individual pitched-note dominant frequencies after filtering:
+14 semitones: 526.978 Hz
+16 semitones: 591.614 Hz
+18 semitones: 663.940 Hz
+21 semitones: 789.001 Hz

The 100 Hz high-pass removes low drift. A 1900 Hz fourth-order low-pass retains
more light upper tone than the previous 1500 Hz cutoff while suppressing high
frequencies. No oscillator, buzzer, reverb, extra metallic sample, compression,
limiting, or random effect was added. Attack/release are smoothly faded, and
all note endpoints are zero. Sampled transitions into silence differ by no more
than 2 PCM steps. The source's naturally short decays become even shorter when
resampled upward.

periodogram, 262144-point FFT, no detrending. Centroid is power-weighted.
Overall RMS includes the full asset duration. Because the revised sounds are
shorter, matching RMS does not imply equal total acoustic energy.

REPRODUCE
Dependencies: Python 3, NumPy, SciPy, ffmpeg on PATH. Exact installed toolchain
versions are recorded in manifest.json. No network or software install is used.

Run from any directory:
    python /path/to/this/folder/build_sounds.py

To remeasure the v2 comparison instead of using the preserved reference values:
    python /path/to/this/folder/build_sounds.py --previous-dir /path/to/v2/folder

To reconstruct from the original supplied archive instead:
    python /path/to/this/folder/build_sounds.py --source-zip /path/to/kenney-interface-sounds.zip

The source and licence hashes are checked before rendering. Pitch uses SciPy
polyphase resampling with a rational approximation denominator at most 10000.
Each note is filtered and faded, mixed at recipe gain, set to the specified
RMS target, and scaled down if necessary to keep peaks at or below -10 dBFS.
Quantization is signed PCM16 with rounding and no random dither.

The script runs format, level, brightness, decode, smooth-end, and exact audition
segment checks. It also confirms sample-by-sample deterministic rendering.
Two consecutive complete builds additionally produced byte-identical WAVs,
manifest.json, and QA-RESULTS.json. REBUILD-VERIFICATION.json records that check.
Exact hashes can depend on the ffmpeg/SciPy versions; reproducibility was
verified using the same installed toolchain.
